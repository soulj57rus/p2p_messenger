# P2P Messenger

Полностью децентрализованный P2P-мессенджер со сквозным шифрованием (E2EE).

## Архитектура

```
┌─────────────────────┐     ┌──────────────────────┐
│   Peer A (браузер)  │     │  Peer B (браузер)    │
│  ┌───────────────┐  │     │ ┌───────────────┐    │
│  │   IndexedDB    │  │     │ │   IndexedDB   │    │
│  │  (Dexie.js)    │  │     │ │  (Dexie.js)   │    │
│  └───────┬───────┘  │     │ └───────┬───────┘    │
│  ┌───────┴───────┐  │     │ ┌───────┴───────┐    │
│  │  Double Ratchet│  │     │ │  Double Ratchet│   │
│  │  (tweetnacl)   │  │     │ │  (tweetnacl)  │    │
│  └───────┬───────┘  │     │ └───────┬───────┘    │
│  ┌───────┴───────┐  │     │ ┌───────┴───────┐    │
│  │   WebRTC DC    │◄─┼─────┼─│   WebRTC DC   │    │
│  │   (PeerJS)     │  │     │ │   (PeerJS)    │    │
│  └───────┬───────┘  │     │ └───────┬───────┘    │
└──────────┼──────────┘     └─────────┼────────────┘
           │                          │
           │    ┌──────────────┐      │
           └────┤  Signal Server├──────┘
                │  (WS + Express)│
                │  (только SDP) │
                └───────────────┘
```

## Технологии

| Компонент | Технология |
|-----------|-----------|
| Frontend | Preact + TypeScript |
| Сборка | Vite |
| P2P | WebRTC (нативный API) |
| Сигнальный сервер | Node.js + Express + ws |
| Шифрование | tweetnacl (NaCl) |
| База данных | IndexedDB (Dexie.js) |
| State Management | Zustand |
| Шрифт | Inter |
| PWA | Service Worker + Manifest |

## Быстрый старт

### 1. Сигнальный сервер

```bash
cd server
npm install
npm start
```

Сервер запустится на `http://localhost:3001`.

### 2. Фронтенд

```bash
npm install
cp .env.example .env
npm run dev
```

Откройте `http://localhost:5173` в браузере.

### 3. Сборка для продакшена

```bash
npm run build
npm run preview
```

## Как пользоваться

1. **Создание аккаунта**: При первом запуске — нажмите "Создать новый аккаунт". Ключи генерируются локально.
2. **Ваш ID**: Публичный ключ отображается в настройках (шестеренка). Скопируйте его.
3. **Добавление контакта**: Введите публичный ключ собеседника в поле ввода ID.
4. **Начало общения**: Когда оба пира онлайн, WebRTC-соединение устанавливается автоматически.
5. **Отправка файлов**: Нажмите на скрепку рядом с полем ввода.
6. **Восстановление доступа**: Сохраните приватный ключ из настроек. При переустановке используйте "Восстановить из ключа".

## Развертывание

### Сигнальный сервер (бесплатный хостинг)

**Render.com** (рекомендуется):
1. Создайте новый Web Service
2. Подключите репозиторий
3. Root Directory: `server`
4. Build Command: `npm install`
5. Start Command: `node index.js`
6. Установите `NODE_VERSION=18` в Environment

**Fly.io**:
```bash
cd server
fly launch
fly deploy
```

### Фронтенд (бесплатный хостинг)

**Vercel**:
```bash
npm i -g vercel
vercel --prod
```

**Netlify**:
```bash
npm run build
npx netlify deploy --prod --dir=dist
```

После развертывания установите переменную окружения `VITE_SIGNAL_URL` с URL вашего сигнального сервера (WebSocket).

## Безопасность

- **E2EE**: Сквозное шифрование через NaCl box (Curve25519 + XSalsa20-Poly1305)
- **Perfect Forward Secrecy**: Реализация протокола Double Ratchet
- **Идентификация**: Ed25519 ключи (signature scheme)
- **Аутентификация**: HMAC-SHA256 для верификации сообщений
- **Ключи**: Хранятся только в IndexedDB на клиенте
- **Метаданные**: Сигнальный сервер не хранит сообщения, только SDP-офферы
